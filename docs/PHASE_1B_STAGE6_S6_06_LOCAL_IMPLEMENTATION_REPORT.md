## Complexity and compatibility

The all-old-snapshot full-restore loop is deleted and replaced by standard Restic metadata operations. Repository selection/credentials, libpq invocation and weekly admission/maintenance are narrow program boundaries; no duplicate application data authority is introduced. The existing OS mutex is moved from per-environment files to one shared empty inode; no backup state table, Worker, Lease, queue, persistent admission ledger or activation framework is added. Complexity increases modestly for the protected tool adapters, direct Migration participation and decisive fixtures, while old-snapshot payload I/O and peak verification scratch allocation converge to one read-back. These are implementation properties, not measured target-host savings.

Existing set-v1 backups remain readable. Temporary compatibility recognizes the previous local weekly source path for retention metadata; no old backup is rewritten. Unknown schemas refuse. Roll back matched Compose/config/program/validator changes together while preserving recovery sets. Do not overlay the new shared Compose validator onto the old immutable Runtime subject.
